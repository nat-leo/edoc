# Deciding on an Approach

## OA

Be speedy, flash the problem quickly. There's no one to talk to, really. So, just solve the problem as quickly as possible while passing all tests. If you can't pass all tests with the solution or don't know it, brute force and hope for the best.

In order to identify a good algorithmic approach, notice the langugae used in the problem and the contraint. These can be hints to solve the problem:

### How to quickly identify the pattern (fast heuristics)
  1. “Longest/shortest subarray/substring” → Sliding window / prefix sums
  2. “Next greater/smaller” → Monotonic stack
  3. “Minimum maximum / maximize minimum” → Binary search on answer
  4. “Prerequisites / ordering with constraints” → Toposort
  5. “Connected components / dynamic connectivity” → DSU
  6. “Grid with multiple starts” → Multi-source BFS
  7. “Count ways” → DP (often)
  8. “All combinations” → Backtracking

## In Person
Always start with brute force. Identify time and 
memory constraints (Big O) 

The optimizations are when Data Structures and Algorithms come in. Use the language of the problem and the contstraints to identify an optimal approach. If multiple approaches can be used, identify the tradeoffs for each approach.
